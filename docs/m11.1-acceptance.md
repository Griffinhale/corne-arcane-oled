# M11.1 resource and hot-path acceptance record

M11.1 is a hardening pass over the physically flashed M11 release candidate.
It does not add presentation or protocol scope. Desktop evidence and physical
evidence remain separate; this record cannot declare final acceptance from
desktop tests alone.

## Implemented hardening

- The renderer now produces QMK's native page-major bytes and hands the full
  512-byte frame to `oled_write_raw()`. The redundant `last_fb` shadow and the
  4,096-iteration per-pixel conversion loop are gone; QMK's own dirty tracking
  remains authoritative.
- Matrix scanning enqueues key-down edges only. Held/released state continues
  to come from the existing level sample, and equivalence tests cover holds,
  release-to-idle, recipes, rapid alternation, and overflow behavior.
- Raw-HID and split seqlocks reject unchanged or in-progress versions before
  copying. Accepted host/split changes drive snapshot/render work; idle loops
  no longer rebuild unchanged state.
- Outcome presentation is wall-clock bounded: impacts remain 600 ms and
  deflects/fizzles 400 ms in normalized 50 ms phases. Dim OLED cadence samples
  those phases rather than stretching an effect to roughly two seconds.
- The display still performs an explicit committed clear before OLED power-off,
  and wake invalidation still forces the current frame back to the panel.

## Desktop verification

- `make test`: all firmware simulator tests and 36/36 host tests pass under
  ASan/UBSan; the no-allocation symbol gate passes.
- Key-down-only equivalence and cadence-independent presentation tests pass,
  including 32-bit timer wrap behavior and dim-policy sample points.
- `make visual-test`: all exact framebuffer hashes and structural visual
  invariants pass.
- `make gallery`: all 37 regenerated PBMs are byte-for-byte unchanged from the
  pre-hardening gallery.
- A clean canonical QMK release compile and a separate diagnostics compile both
  link successfully for `crkbd/rev1` converted to `rp2040_ce`.
- Raw HID remains 32 bytes, split v7 remains 31 bytes, and `sim_world_t`
  remains 56 bytes. No protocol version or authoritative mechanics changed.

## Acceptance status

The M11.1 desktop/release candidate is verified; M11.1 is **not physically
accepted**. This session did not flash either half. Physical flash,
either-half wake, five-minute continuity, host-flood typing stress,
suspend/resume, split-link recovery, diagnostic timing/counters, real-panel
effect duration, and rollback remain pending until run on the keyboard.

### Merge disposition (2026-07-14)

The project owner explicitly waived the pending M11.1 physical gate for the
purpose of merging this desktop-verified candidate and beginning M11.5. This
is a release-policy waiver, not physical evidence: none of the pending checks
above are represented as having passed. M11.5 retains its own physical timing,
split-recovery, typing-stress, suspend/resume, and rollback acceptance gates.

The audit's recommended M11.5 A1-A4 work is intentionally deferred: diagnostic
backchannel, real-notification integration harness, canonical application
profiles, and event-driven host scheduling. No M12 living-stage art or game
expansion belongs on this branch.
